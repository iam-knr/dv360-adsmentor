## 1. How to use this file

### 1.1 Rules for build sessions
1. If a spec sentence and an RC row disagree, the RC row wins.
2. Where a spec file already carries a line `> Resolved RC-0xx`, the text around it was edited to match the row. Where the edit column says "none", the row is a decision that the owning module already follows.
3. Module `Δ` rows (spec deltas) are adopted as part of the spec they target (RC-052). Each module's first build task applies its deltas as a migration or constants change.
4. Open questions in module section 8.1 keep their stated default. Only the `OWNER` rows below may change a default, and only the owner can change them.

### 1.2 Authority order and the one exception
Default order: DM > VAL > RT > ENG > DS > modules.
- Applied as written for fields, structure and semantics (for example `version` column, `Alert` table, DM `FrequencyMode`).
- **Exception for enum key spellings** (RC-001 to RC-004): where VAL, RT and the module files agree on a spelling that differs from DM, the majority spelling wins, because the Prisma schema does not exist yet and a rename is one edit in DM now but a migration later.
- ENG wins on anything the engine computes or stores (RC-021, RC-022, RC-023, RC-034).
- RT wins on route, action and endpoint names (RC-015, RC-027, RC-052).
