## B. Found while building

| # | Finding | Action |
|---|---|---|
| B1 | The Investigate drawer opens only for a conflicting-settings row that stands for exactly one entity. A row for several entities links to the filtered list (see A1) | none |
| B2 | Seeded alerts (`lib/seed/plan.ts`) use severity `CRITICAL` for no-spend alerts, the engine raises them as `NEEDS_ATTENTION`. Both are handled; the panel sorts `CRITICAL` first | none |
| B3 | `Alert.title` is stored with N = 1. The panel and the Alerts page build their own plural-aware text from the engine code and the count, and fall back to the stored title for codes without a template (`SPEND_THRESHOLD`) | none |
| B4 | Apply goes through `updateInsertionOrder` / `updateLineItem`, so the normal validation applies. IO-055 refuses automatic budget allocation on an insertion order whose bid and budget are automated; the engine only suggests it for line-item-controlled insertion orders, so this shows only when the setting changed after the suggestion was written. The failure comes back as `INVALID` with the rule message | none |
| B5 | Live status is not stored. The Troubleshooter banner is derived at read time from the lifecycle (status, parents, flight, budget segments) and `liveStatusFromFunnel` over the selected range. `NO_ACTIVE_DEAL` is never produced | A5-like follow-up if wanted |
| B6 | No `LOOKUP_PAGES` change: the Troubleshooter and Alerts pages look up the placeholder `{liId}` and `{cid}`, which are real ids in the shell smoke world, so they return 200 | none |
| B7 | The Troubleshooter Sankey is a hand-drawn SVG (no chart library): five nodes, link bands and one red "filtered" band per stage, hover highlights the stage table | none |
