# P4-10b experiments and lift: what is not done

Branch `p4-10b-experiments`, module 17 (`docs/specs/modules/17-experiments.md`), tasks M17-01 to M17-11. No migration: every Δ17 column and enum value (`SCHEDULED`, `ENDED`, `version`, `channelScope`, `endedAt`, `LiftFlight` fields) was already in `0002_extended`. Everything below is a known gap or a decision, with the reason.

| # | Gap or decision | Reason / where it goes |
|---|---|---|
| 1 | AB and LS rules live in `lib/experiments/rules.ts`, not in `lib/validation/rules/experiments.ts` (which stays empty); `validation.md` is not edited | The validation docs-sync and coverage tests tie every registered id to the spec tables and to `cases.*.ts`. Same choice as `PLN` in P4-08. Move them when the validation owner adds the AB and LS case files |
| 2 | The report is computed at read time; the `ExperimentResult` cache table is not written | The spec allows "computed at read when missing" (Δ17-6). Volumes are small |
| 3 | `getAbReport` uses `lib/experiments/stats.ts`, not an engine function `engine.experimentReport` | Spec 4.5 allows "an equivalent pure function". Z critical values are read from `engine/params.json` in the tests only; `stats.ts` holds the same numbers (1.645, 1.96) |
| 4 | Reach in the report is the sum of the latest `SimReachSnapshot` per line item (overcounts users shared between line items); without a snapshot it is impressions at a frequency of 2.4. The reach "rate" test is reached users per impression | `SimReachSnapshot` has no per-arm rows (`docs/gaps/p3.md`) |
| 5 | The arm supply share is `split × (1 − contamination) + (1 − split) × contamination`, or `split × identifiedOnlyShare` with Exclude unidentified users. Applied as `LineItemEntity.supplyShare` in `runFunnel` (`Math.round(requests × share)`) | Engine 6.7 gives the parameters but not the combination. Line items outside an active test are untouched (golden tests unchanged) |
| 6 | Lift eligibility "your media cost" is the trailing media cost over the window (10 or 28 days) ending today, not past plus a forecast of the remaining flight | Spec says "at the current run rate `[SIM]`"; trailing spend is the run rate |
| 7 | A flight completes when its percent reaches 100, without waiting for the window end | AC 14 ("at 100% … View report enables"); spec 4.2 also names the window end |
| 8 | Survey sizes: `responsesPerArm = floor(mediaCost / costPerResponse / 2)`, times 3 for Enhanced; the reference pool is 1.5 million users, `r0` 0.15; slice values for Age, Gender, Device and publisher slices are fixed tables | Engine 6.8 leaves these open |
| 9 | YouTube programmatic guaranteed IOs are found through `LineItemInventory` deals of type `PROGRAMMATIC_GUARANTEED`; the seed has none, so the PG group of the IO picker is empty | No seeded PG line items |
| 10 | The Settings and Difference panels use real parallel and intercepting routes (`e/[testId]/@panel/(.)report/…`). "Open in full page" is a plain link (document load) | Same URL, panel on soft navigation, page on hard navigation (AC 9) |
| 11 | Dates in the forms are native date inputs; no `DvDateRange` | Same as `docs/gaps/p4-07.md` #5 and `p4-08.md` #7 |
| 12 | Lift study `strength`, `language` and `objectType` are stored on the study; a second flight reuses them. Add flight does not let the student change the IOs | Q8 assumed the same IOs |
| 13 | Ending an A/B test early moves its end date to today; the report range is frozen at that date. Arm membership is not logged on the IOs and line items (Q3); the lift study created from an A/B test is linked by `originExperimentId` and `liftStudyId`, which are not logged fields | Spec 4.7 |
| 14 | The end-to-end tests do not run the engine: spend rows are written to `SimDailyMetric` and the sim clock is set by hand; the engine steps are called directly (`advanceExperiments`, `advanceLiftStudies`) | A 7-day fast-forward costs minutes per sandbox (`docs/gaps/p3.md` A3) |
| 15 | `Download` on the report is a CSV of the tiles per arm; the Lift report has no download or ⋮ menu | Low value for the exercise |
| 16 | Search lift needs YouTube or Demand Gen line items (MX-13); with only a Display IO the type is disabled (LS-005). The unseeded search base cost (600,000 INR, Q5) and the 28 day window are `[SIM]` | Q5 |
| 17 | The seeded ACTIVE test pair is chosen as the two Display line items with the smallest click through rate difference, and the COMPLETED pair as the largest, over the seeded history stub. Whether the completed one is significant at 90% depends on that stub | Seed cannot control the stub |
| 18 | Not built: a notice in the bell when a lift study becomes eligible (stretch in 4.7); Troubleshooter reason for reduced supply of arm entities (Q4) | Out of v1 |
