# P4-12 history and notifications: what is not done

Branch `p4-12-history`, module 05 (`docs/specs/modules/05-history-notifications.md`), tasks 05-T3 to 05-T10. No migration: every column the module needs (`HistoryNote`, `Notification`, `NotificationDismissal`, the `ChangeGroup` additions) was already on `main`. Everything below is a known gap or a decision, with the reason.

| # | Gap or decision | Reason / where it goes |
|---|---|---|
| 1 | Registries (05-T3) are not complete for all 21 entity types: `TARGETING_TEMPLATE` and `REPORT` have none, so their groups render with default formatting. The "every Prisma column is registered or ignored" test of AC-05-29 was not added | Those entities have no writer yet (reports: `docs/gaps/p4-07.md`). Add the registry with the module that writes the entity |
| 2 | `lib/changelog/index.ts` (P3-05a) changed: an entity is now part of its own chain (`ioId` for an IO, `lineItemId` for a line item, and so on) | `patchIoBudget`, `updateInsertionOrder` and the line item writes passed only the parents, so the IO and LI History pages could not find their own groups (found by PW-05-1). One central fix instead of editing every service. Groups written before this fix are not repaired |
| 3 | `HistoryNote` was added to `UI_STATE_TABLES` (`lib/changelog/ui-state-tables.ts`) | Notes are annotations, not changes (spec 4.6). The scan does not cover `lib/history` today; this keeps it green if the roots grow |
| 4 | The default History range ends at the later of sim today and wall-clock today in the display zone | User changes are stamped with real time (Q2), the sim clock can be behind it, so "90 days to today" on sim time alone would hide a change made a moment ago. The Spend chart still uses sim days from `SimDailyMetric` over the same dates, so it can be empty when the sim clock is far behind |
| 5 | "Include local timezone" sends the browser zone (`zone=`) to the API; the first server render of a URL with `tz=local` uses the advertiser zone and the page reloads the data once on mount | The server cannot know the browser zone |
| 6 | No engine writers (05-T9): `SIM_ENGINE` budget allocation groups (spec 4.1.5), the "Sandbox reset" instructor row (AC-05-28) and scenario loader groups are not written. AC-05-27 and AC-05-28 are open | They need the P3-08 runtime and the Phase 5 instructor console; the pipeline and the labels ("Simulator engine", "Scenario", "Instructor") are ready |
| 7 | PW-05-5 (creative History) and PW-05-6 (bulk pause and partner fan-out) have no Playwright test in `history.spec.ts` | Bulk grouping, fan-out and hidden rows are covered at the database level in `tests/changelog/withChangeLog.db.test.ts`; the creative page is covered by `tests/creatives/service.db.test.ts`. The new creative layout (range chip, "Items per page: 25", `dd/mm/yyyy hh:mm`) has no browser test |
| 8 | Creative History: the date range chip can be removed (shows all changes) but not edited; "Add a filter" offers User and Field only. Day and range bounds use UTC in the service (`from`/`to` are not shifted to the advertiser zone). The pager keeps Previous and Next | `docs/gaps/p4-01` style; a date picker chip needs a `DvFilterBar` date field type |
| 9 | Floodlight group History (`fl/history`) and the Deal History tab keep the table layouts P4-04 and P4-02 built. The spec prefers day cards for Floodlight (`DayCard` is exported from `components/history`) | Switching would rewrite `tests/e2e/resources.spec.ts`; no loss of data |
| 10 | The bell shows announcements above report-run messages. No "Mark all read" and no per-kind icon; the pinned flag is honoured in ordering only | Module 01 owns the bell shell |
| 11 | Instructor announcements: `createAnnouncement` and `deleteAnnouncement` exist and are tested but have no UI (Phase 5 console). A Super admin may announce platform-wide; an Admin only to a cohort in their scope | Spec 1.2 |
| 12 | Validation ids `HIS-001` to `HIS-004`, `HIS-010`, `HIS-011` and `HIS-020` live in `lib/history` constants, not in `lib/validation` (same choice as `PLN`, `AB`, `LS`) | The validation docs-sync tests tie every registered id to `validation.md` |
| 13 | Performance AC-05-30 (500 groups in 3 s, 90-day read of 5,000 groups in 300 ms with `EXPLAIN`) is not asserted. The reader makes two queries (ids and times of all groups in range, then entries of the first 30 days) | Fine for classroom volumes; revisit with a day column on `ChangeGroup` if a sandbox grows past about 20,000 groups |
| 14 | Notes cannot be added to a day with no changes (Q6), and only the four History entity types take notes | Spec |
| 15 | Keyboard `Cmd/Ctrl+Shift+L` downloads the CSV from the History page only; it is not registered in the shortcuts dialog | Module 01 owns the dialog |
| 16 | `LOOKUP_PAGES` in `tests/e2e/shell.spec.ts` needed no new entry: the four History routes look their entity up by the real `{cid}`, `{ioId}` and `{liId}` ids of the test world, not by `{x}` | The shell spec passes |
