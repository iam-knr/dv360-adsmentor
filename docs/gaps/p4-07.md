# P4-07 reporting: what is not done

Branch `p4-07-reporting`, module 16 (`docs/specs/modules/16-reporting.md`). Everything below is a known gap, with the reason.

| # | Gap | Reason / where it goes |
|---|---|---|
| 1 | `ChangeGroup` entries for reports (create, rename, delete, schedule; 4.9) are not written | The change-log registry for a `REPORT` entity belongs to P4-12 (change history). |
| 2 | The toolbar **Download** streams a file without a stored `ReportRun` (spec: an unsaved run marked `adhoc`) | `ReportRun.reportId` is required; an ad hoc run would need a throwaway report. The file is identical. |
| 3 | **Run report** saves an unsaved report first (so the run has a report to hang on) | Same reason. A new report appears in the hub after its first run. |
| 4 | Report files live in the Blob store when `BLOB_READ_WRITE_TOKEN` exists, otherwise in server memory; a download whose file is missing is rebuilt from the run's definition and fixed date range | Blob is owner item P-08. Deletion after 30 real days (4.4) is not implemented. |
| 5 | The date range control is a preset select plus two native date inputs, not `DvDateRange` | `DvDateRange` needs a preset set and a `today` Date per field; the report presets are tokens. Same results. |
| 6 | **Guided tour** is a four-step modal, not a `DvTooltip` tour | `[SIM]`, low value. |
| 7 | **Custom data** dialog (S8, stretch) | Out of scope for v1. |
| 8 | Sharing needs a second person who resolves to the same sandbox. The app only resolves a sandbox for its owner, so a shared report cannot yet be opened by the second person in a browser (E2E-RPT-06 stops at the `ReportShare` row; the service rules are covered by `tests/reporting/service.db.test.ts`) | Sandbox resolution for granted users is module 19 / 18. |
| 9 | Seed: no shared report in the starter sandboxes | Same reason as 8. |
| 10 | E2E-RPT-05 does not advance the clock in the browser; schedule save and the `runDueReports` hook (one run per sim day, fast-forward cap of 10, idempotency, inbox messages) are covered by `tests/reporting/runs.db.test.ts` and `schedule.test.ts` | The instructor clock API is P5. |
| 11 | Bell shows the last 10 inbox messages and marks them read on open. No unread badge, no "mark one as read" | The notifications UI is P4-12. |
| 12 | Cross-media reach reports | Planning module (P4-08). The hub does not link to them yet. |
| 13 | `reporting.maxRows` (Δ16-9) is a constant (200,000), not a `PartnerFeatureFlag` read | The flag UI is in settings (P4-09). |
| 14 | Pivot table is computed in the browser from the flat result (one COLUMNS dimension) | Enough for the preview; files are flat. |
