# P4-03 gap list (audiences)

What module 14 still lacks after the P4-03 PR, and what other modules need to do for it. Size: S under half a day,
M about a day, L two days or more. Task ids are module 14 tasks (`docs/specs/modules/14-audiences.md` section 7).

## A. Not done in module 14

| # | Gap | Task | Size |
|---|---|---|---|
| A1 | Tag-based lists do not grow over time. The size is fixed at creation (3,000 to 60,000, seeded by name) and copied when the list becomes active. Spec 5 asks for `0.6 × raw` growth per tick and a 0.5% daily decay, driven by `SimConversionDaily` | M14-09 | M (engine) |
| A2 | `advanceAudiences` lives in `lib/audiences/lifecycle.ts` and is called from `persistTick` step 8. It is not a pure module in `lib/engine` with unit tests of its own, and `engine.estimateAudienceSize` is not used by the Impressions Estimator or the combined summary (they use `lib/audiences/sizes.ts`). The targeting panel's own estimate (`/api/dv/audiences/estimate`) still uses the engine and can differ slightly from the numbers shown here | M14-09 | M (engine) |
| A3 | `engine.geoDistribution` and `engine.audienceComposition` (Δ14-14) are not engine functions. `lib/audiences/analysis.ts` computes both from a hash of the seed list or line item and a fixed regional population table (IN, US, SG). They do not use `SimDimAllocation` shares, so the numbers do not match report breakdowns | M14-10 | M (engine) |
| A4 | After an archive the next tick only sees `config.restricted = true` on the list (the engine's restricted audience flag, alert `RESTRICTED_AUDIENCE_LIST`). The engine still loads archived lists and matches them; "no longer matches" and the conflict alert one tick later (AC 13, E2E-AUD-06 last step) are covered by the db test on the config flag, not by a tick in the browser | M14-09 | S (engine) |
| A5 | The Google audience catalogue is `data/reference/google-audiences.json` (the file the targeting panel already reads). The `GoogleAudience` table is not seeded, so there is no per-inventory size or eligibility column: sizes come from `googleAudienceSize()` (share of the pool by kind) and every row is eligible where its size is 1,000 or more. Detailed demographics and life events are only as complete as the JSON | M14-01 | S |
| A6 | `AudienceSizeHistory` (Δ14-9, growth chart on the details page) is not built; it was optional | M14-08 | S |
| A7 | Picker `PAIR`, `LINEAR_TV` and `THIRD_PARTY` categories return no rows (no seed). `searchAudiencePicker` is built and tested but the targeting panel (P3-07) still reads its own `/api/dv/audiences/estimate/catalogue`; switching it over to the service is a follow-up | M14-06 | S (module 10) |
| A8 | The combined form uses a two-pane picker dialog (`DvPickerDialog`) with all categories in one list, not the `DvAudienceBuilder` with category tabs and breadcrumb paths. Google audiences are capped at 200 rows in the dialog; type to search the rest | M14-06 | S |
| A9 | Customer match: the browser hashes identifiers for all four contact types and the template download has a sample file for each, but there is no row-level validation of values (only the header, AUD-021) and no error report download. "Connect a new product" picks one of three seeded products and produces a synthetic row count | M14-05 | S |
| A10 | The lookalike form lists seeds as checkboxes (up to 10) with their user counts, not a searchable picker dialog. Country list is ten countries, not the full geography tree | M14-07 | S |
| A11 | Details page: the "Learn more" help is a short text in a slide-over for the type picker only; the Audience details page has no unsaved-changes dialog on the tab switch beyond the shared guard. The Download CSV and column picker of the list pages (spec S1 to S4 common) are not built; the filter bar has Type and Status and a Name/ID search | M14-03 | S |
| A12 | The Line items tab is a plain grid (name, ID, type, status, targeting mode) and not the standard line item grid with Performance menu, date range, download and fullscreen. It shows no metrics from `SimDailyMetric` slice `audience` | M14-08 | M (module 08 grid) |
| A13 | Audience alerts (red bell on a list row through `TargetingAssignment`) are not joined to the list pages | M14-03 | S |
| A14 | `bulkAudienceAction` archives or unarchives in one transaction and writes History per list, but no `BulkJob` row (spec 4.5). Bulk edit is P4-10 | M14-03 | S (P4-10) |
| A15 | The data model's AUD-110 lock is enforced for the fields the details form could send (`locked` map in `updateAudience`); the UI does not render locked fields as editable, so the rule only guards hand made calls | M14-08 | S |
| A16 | Customer match "membership duration" is not shown on the details page for connected products without a duration, and the tag-based details page does not show the rule list as editable (locked by spec) | M14-08 | S |
