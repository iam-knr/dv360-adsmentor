# P4-05 custom bidding: what is not done

Branch `p4-05-bidding`, module 15 task M15-08 (`docs/specs/modules/15-resources.md` S7, 4.3). Everything below is a known gap or a decision, with the reason.

The brief for this session also named "the automated bidding items listed for P4-05 in build-plan 3.7". Section 3.7 lists only M15-08 for P4-05. Automated bidding itself (the 16 strategies, learning, lambda) was built in P3-08a; the only automated-bidding part that waited for P4-05 is the algorithm picker for the two custom value strategies, which is built.

| # | Gap or decision | Reason / where it goes |
|---|---|---|
| 1 | The engine does not score impressions with the algorithm. `MAX_CUSTOM_VALUE_COST` and `TARGET_CUSTOM_VALUE_COST` still map to the nearest built-in goal (`lib/engine/bidding/strategies.ts`); the algorithm only trains (P4-04 hook) and shows readiness | Needs `loadWorld` to carry algorithms and `valueModel` to read `score`/`status` (engine.md 4.3). Engine session (`docs/gaps/p3.md` #8) |
| 2 | A suspended algorithm blocks line item saves (`LI-047`/`CB-011`) but already running line items keep delivering | The engine has no "algorithm suspended" reason code. Goes with gap 1 |
| 3 | `LI-047` now accepts a `TRAINING` algorithm; the spec text says "not Active" is an error | Contradicts module 15 6.1 item 14 (a line item shows the `CB-010` warning while the algorithm trains, which is impossible if it cannot be attached). `CB-010` is a warning on the algorithm and on the line item picker, `LI-047` still blocks `SUSPENDED` and unknown ids. Case `X-LI-047 ... training algorithm` in `tests/validation/cases.li.ts` |
| 4 | The "+20 %" error rate when a multiplier signal is unavailable is read as 20 % of the base rate (0.5 % becomes 0.6 %) | Engine 4.3 writes `0.5% + 20%` without saying relative or absolute; 20.5 % errors on a normal algorithm looked wrong. Recheck in SOP-3 |
| 5 | Migration `0009_p4_05_custom_bidding_draft` adds `CustomBiddingAlgorithm.isDraft`. A wizard row is a draft (hidden from the list, from line item pickers and from History) until step 3 saves it; leaving the wizard at step 1 or 2 leaves an unlisted draft row | Needed because the Test step needs a stored algorithm (`CustomBiddingTestRun.algorithmId`). Drafts are not purged yet (add to `retention` in the engine runtime) |
| 6 | Editing a saved algorithm changes it in place at step 1 "Next" (reset to Training, readiness 0, test cleared), before Test and Save; leaving the wizard there keeps the reset | Simplest way to honour "editing rules resets it to TRAINING and re-requires Test". A copy-on-edit would double the rows |
| 7 | `Save and activate` only matters for a suspended algorithm (new algorithms always start in Training; the engine activates them at 100 % readiness) | Spec: "Created `TRAINING`, becomes `ACTIVE` when readiness reaches 100%" |
| 8 | Owner (Advertiser or Partner) can be chosen only on the first save of an advertiser-created algorithm. An algorithm made at partner level is partner owned. A saved algorithm cannot move between levels | Spec does not describe re-parenting |
| 9 | `sampleImpressions` takes a plain `SampleMix` (format weights from the advertiser's non-archived line items, Floodlight activity ids), not the full engine `world`. The sample is generated with fixed signal rates, not from the engine's supply cells | Δ15-14 shape was left open (RC-026). Replace the rates with supply cell values when the engine session lands |
| 10 | The Test histogram is a bar chart in a `DvChartCard` with 20 equal-width bins from 0 to the highest score | Spec asks for 20 bins only |
| 11 | Script custom bidding stays disabled (card shown, no tables written) | RC-037 |
| 12 | Goal-based (`GOAL`) algorithms are not creatable; the column exists for the source label | Not in the v1 wizard (module 15 S7) |
| 13 | The Summary and Execution sections of the list are KPI tiles (counts), not charts | Spec names cards only |
| 14 | No Playwright step attaches an algorithm to a line item in the browser. The picker is on the line item form (`LiForm`), the rule is covered by `tests/validation/cases.li.ts` and the service by `tests/resources/custom-bidding.db.test.ts` | The shell world's IO is not automated with a custom value strategy; building one needs the IO form |
| 15 | Delete is refused with the message "This algorithm is used by {n} line items." as a warning in the result (code `CB-013`), not as a modal | Same pattern as channel and list delete in P4-04 |
