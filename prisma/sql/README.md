# prisma/sql

Owner session: P3-05a.
Spec: data-model.md Appendix B. Do not edit from another session (build-plan 3.2).

These files hold the SQL that Prisma cannot express. `prisma/migrations/0001_core/migration.sql` is the Prisma generated DDL with these files inlined in file order (00, 10, 20, generated tables, 30, 40, 50). `tests/unit/migration-core.test.ts` fails when a file here and the migration differ.

| File                          | Content                                                                                       |
| ----------------------------- | --------------------------------------------------------------------------------------------- |
| `00-extensions-sequences.sql` | `citext`, `entity_public_id_seq`, `next_public_id()`                                          |
| `10-roles.sql`                | roles `app_tenant` and `app_engine`; falls back to a notice when the host refuses a privilege |
| `20-rls-function.sql`         | `app_enable_tenant_rls(table)`: enables RLS, creates the two policies, grants                 |
| `30-constraints.sql`          | `NULLS NOT DISTINCT` unique indexes and the one-owner checks                                  |
| `40-rls-apply.sql`            | generated by `npm run db:gen-rls`, one call per table with a `sandboxId` column               |
| `50-grants-and-defaults.sql`  | privileges and the `AccountPolicy` row                                                        |

Migrations deploy to the live shared database. Keep them additive: no drops, no data rewrites. Later migrations use `app_enable_tenant_rls` for new tenant tables instead of editing these files.
